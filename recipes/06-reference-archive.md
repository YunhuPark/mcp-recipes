# 레시피 06. 레퍼런스 자동 아카이빙

> **Claude + 브라우저 + Notion**
> 마음에 든 랜딩페이지, 광고, 카피의 링크를 주면 훅·구조·CTA를 분석해서 Notion 레퍼런스 DB에 쌓습니다.

| 항목 | 내용 |
|---|---|
| 결과물 | Notion 레퍼런스 DB (이름, URL, 유형, 훅 분석, 구조, CTA, 태그, 수집일, 한계 메모) |
| 필요한 도구 | Claude, 브라우저 도구, Notion |
| 난이도 | 공개 웹페이지: **하** / 로그인이 필요한 소스(인스타그램 등): **중~상** |
| 사전 준비 | Notion 연결 (브라우저는 Claude 데스크톱 앱에 내장된 것을 사용) |
| 실제 소요 시간 | 공개 페이지 3개 열람 + 분석 + 저장 + 인스타그램 한계 확인까지 **약 2분 10초** |
| 검증 일자 | 2026-10-09, 직접 실행 |

> ⚠️ 이 레시피는 원래 **Claude in Chrome(내 크롬)** 으로 구상했지만, 이번 검증은 Claude 앱에 내장된 **내장 브라우저**로 했습니다. 내 크롬 로그인 상태를 쓰는 경로는 **검증하지 않았습니다.**

---

## 이런 분께 맞습니다
- 참고용 랜딩페이지와 카피를 보는 족족 모아 두고 싶은 마케터
- "저 페이지 구조가 왜 좋았지?"를 나중에 다시 찾아볼 수 있게 정리하고 싶은 분

## 이런 분께는 안 맞습니다
- 인스타그램 게시물이나 로그인이 필요한 페이지가 주 소스인 분 (아래 "막힌 것" 참고)
- 디자인과 시각 표현 자체를 수집하려는 분 (텍스트 분석으로는 한계가 큽니다)

---

## 진행 순서

1. **DB 만들기**: 이름, URL, 유형, 훅 분석, 구조, CTA, 태그, 수집일, 한계 메모 칸이 있는 Notion DB를 만듭니다.
2. **페이지 열기**: 링크를 브라우저에서 열고 본문 텍스트를 읽습니다.
3. **분석**: 훅(첫 메시지), 구조(섹션 흐름), CTA를 요약합니다. **원문을 통째로 저장하지 않고 분석만** 기록합니다.
4. **저장**: 분석 결과를 DB 항목으로 넣습니다. 각 항목에 "한계 메모"를 남겨 무엇을 못 봤는지 적습니다.
5. **검수**: AI가 쓴 분석 문장에도 오타와 틀린 해석이 있을 수 있으니 훑어봅니다. **(생략 금지)**

---

## 시작 프롬프트 (그대로 복사해서 쓰세요)

```
아래 링크들을 레퍼런스로 아카이빙해줘.

[링크 1]
[링크 2]
[링크 3]

순서:
1. Notion에 '레퍼런스 아카이브' DB를 새로 만들어줘.
   (칸: 이름, URL, 유형, 훅 분석, 구조, CTA, 태그, 수집일, 한계 메모)
2. 각 링크를 열어 본문을 읽고, 훅·구조·CTA를 분석해서 DB에 넣어줘.
3. 원문 문장을 길게 옮기지 말고 요약과 분석만 적어줘. 인용이 필요하면 짧게.
4. 페이지에 보이는 숫자가 데모 화면의 예시 값처럼 보이면 그렇게 표시해줘.
5. 열 수 없거나 내용이 일부만 읽히는 페이지는 '한계 메모'에 무엇을 못 읽었는지 적고,
   내용을 추측해서 채우지 마.
```

## 실제로 돌려보고 알게 된 것

### 잘 된 것
- 공개 마케팅 페이지 3곳(Notion, Canva, 토스 한국어 홈) 모두 **본문 텍스트를 읽고 분석해서 Notion에 저장**하는 데 성공했습니다.
- 3곳 모두 훅, 섹션 구조, CTA 패턴이 구분되게 정리됐고, 태그와 수집일까지 한 번에 채워졌습니다.
- 각 항목에 "한계 메모"를 남기게 하니, 나중에 이 분석을 어디까지 믿어도 되는지 알 수 있었습니다.

### 막힌 것, 주의할 것

| 문제 | 실제로 일어난 일 | 대처 |
|---|---|---|
| **텍스트 잡음** | 캐러셀 문구가 3번씩 반복되어 나오고, 세로로 쪼개진 글자("내 자 산"), "새 탭에서 열기" 같은 접근성 문구가 섞임 | 분석 단계에서 반복과 잡음을 걸러내라고 시키세요. 원문 그대로 저장하지 마세요. |
| **시각 요소는 못 봄** | 텍스트만 분석했기 때문에 레이아웃, 색, 영상은 확인하지 못함. 디자인 도구(Canva)는 핵심이 시각 요소라 한계가 큼 | 시각 레퍼런스는 이 방식으로 수집하지 마세요. |
| **인스타그램은 프로필 헤더만** | 프로필 이름, 팔로워 수, 소개글만 읽히고 **게시물 본문과 이미지는 읽히지 않음**. "게시물 더 보기" 안내가 나옴 | 인스타그램 레퍼런스는 **사용자가 캡션을 붙여넣거나 스크린샷을 주는 방식**을 쓰세요. 아래 "직접 주는 방식"에서 시험했습니다. |
| **스크린샷이 불안정** | 인스타그램에서 스크린샷이 5초 제한을 넘겨 한 번 실패했고, 재시도하니 창이 작게 렌더링되어 화면의 일부만 보임 | 이번 검증에서는 스크린샷 분석을 신뢰하지 못했습니다. |
| **데모 UI 숫자** | 토스 페이지의 금리, 판매량은 데모 화면의 예시 값인데 본문 텍스트에는 실제 수치처럼 섞여 나옴 | 시작 프롬프트 4번처럼 "예시 값" 구분을 시키세요. (이 지시가 효과 있는지는 검증하지 못했습니다.) |
| **AI가 쓴 분석에도 오타** | 저장한 분석 문장에 "흩어진"을 "흘어진"으로 쓴 오타가 1건 있었음 (직접 고침) | 5단계 검수를 하세요. |
| **Notion 칸 이름 함정** | 칸 이름이 정확히 "URL"이면 입력할 때 `userDefined:URL`로 써야 했음. 레시피 4번의 "Canva 링크" 칸은 접두사가 필요 없었음 | 칸 이름이 `URL`, `id`로 정확히 일치하면 접두사가 필요하다고 기억하세요. |

### 로그인형 소스는 내가 직접 주는 방식 (검증함, 합성 이미지 기준)

링크를 못 읽는 소스는 **캡션 텍스트를 붙여넣거나 스크린샷(이미지)을 직접 주는** 방식으로 대신합니다. 2026-10-13에 시험했습니다.

| 입력 방식 | 확인한 것 | 결과 |
|---|---|---|
| **이미지로 주기** | 무작위 문구 이미지 3장에서 글자를 읽고 정답과 대조 (**블라인드**) | 깨끗한 글자, 작은 글자, 노이즈 위의 작은 글자 모두 **18줄 중 18줄 완전 일치** |
| 이미지로 주기 | 글자 이외의 시각 구성 분석 (배치, 색, 위계) | 가능함. 링크를 읽는 방식으로는 못 보던 정보임. **정확도는 채점하지 않음** |
| **캡션 텍스트 붙여넣기** | 붙여넣은 문구를 분석해 Notion DB에 저장 | 저장까지 성공 (자작 문구 1건) |

시험 방법: 이미지는 PowerShell로 무작위 단어, 숫자, 영문 코드를 그려 만들고 **정답을 파일에만 저장해 두었다가, 이미지를 읽은 뒤에 대조**했습니다. 어려운 이미지(작은 글자, 노이즈)에서도 일치했고, 노이즈 쪽의 `I`, `l`, `1`처럼 헷갈리는 글자는 읽을 때 불확실하다고 표시했는데 결과적으로 맞았습니다.

**이 결과를 과신하면 안 되는 이유**
- 이미지는 **컴퓨터로 만든 합성 이미지**(깨끗한 글자, 작은 글자, 노이즈 위의 작은 글자 각 1장, 한 글꼴, 짧은 줄 6개)입니다. 실제 인스타그램 스크린샷의 압축, 장식 글꼴, 이모지, 긴 캡션, 손글씨는 시험하지 않았습니다.
- 캡션 입력은 **자작 문구**라서 제3자 카피를 분석하는 품질은 모릅니다. 해시태그, 이모지, 줄바꿈이 보존되는지도 확인하지 못했습니다.
- 처음 설계에서 실수가 있었습니다. 두 이미지에 같은 정답을 써서, 첫 이미지를 본 뒤 두 번째를 읽은 것은 **블라인드가 아니었습니다.** 그 결과는 버리고 새 무작위 문구로 다시 시험했습니다.

**주의**
- 스크린샷에는 **계정명, 다른 사람의 댓글, 개인 메시지**가 함께 찍힐 수 있습니다. 필요한 부분만 잘라서 주세요.
- 남의 게시물은 **분석과 요약만 저장**하고 원문을 길게 옮기지 마세요.
- AI가 쓴 분석 문장에는 여전히 오타가 났습니다. 이번에도 "캡션"을 "캐션", "머그컵"을 "머그컬"로 쓴 것을 발견해 고쳤습니다. **저장 후 검수는 필수입니다.**

### 아직 검증하지 못한 것 (솔직하게 밝힙니다)
- **Claude in Chrome(내 크롬)**: 이번엔 내장 브라우저만 썼습니다. 내 크롬의 로그인 상태를 쓰면 로그인이 필요한 페이지도 읽을 수 있을 수 있지만, **검증하지 않았고** 내 계정 권한으로 동작하는 만큼 주의가 필요합니다.
- **로그인이 필요한 페이지**: 인스타그램은 로그인 없이 읽히는 부분까지만 확인했습니다.
- **실제 인스타그램 스크린샷**: 위 이미지 입력 시험은 합성 이미지였고, 실제 화면(장식 글꼴, 이모지, 압축)은 시험하지 않았습니다.
- **제3자 캡션 분석 품질**: 자작 문구 1건만 시험했습니다.
- **광고 라이브러리 등 동적 검색 사이트**: 해보지 않았습니다.
- **대량 수집** (수십 개): 3개만 했습니다.
- **사이트 약관과 접근 제한**: 공개 페이지를 한 번씩 열람한 것이 전부입니다. 반복적이거나 대량 수집을 할 때 각 사이트의 약관과 접근 제한은 직접 확인하세요.
- **다른 업종, 다른 언어**: 한국어 사이트 3곳만 봤습니다.

## 결과 예시 (공개 페이지 3개)

| 이름 | 훅 | 구조의 특징 | CTA |
|---|---|---|---|
| Notion 한국어 | 팀과 AI 에이전트가 함께 일한다는 협업 관점 | 가치 제안 → 기능 3개 → 활용 사례 → 고객 인용 → 숫자 증거 | 무료 시작 + 데모 요청 2단 |
| Canva 한국어 | 쉽다는 약속 + 구체적 산출물 나열 | 카테고리 탭 → 기능별 한 줄 카드 다수 | 무료 시작 + 카드별 "더 알아보기" |
| 토스 | 흩어진 서비스를 하나로 | 서비스별 섹션 반복 (불편 → 해결 → 한 줄 행동) | 섹션별 동사형 마이크로 CTA |

위 분석은 **텍스트 기반 해석**이고 제가 직접 요약한 것입니다. 각 사이트의 의도나 성과를 확인한 것은 아닙니다.

## 마무리 체크리스트

- [ ] 분석 문장에 오타나 틀린 해석이 없는가
- [ ] 데모 화면의 예시 숫자를 실제 수치로 기록하지 않았는가
- [ ] 읽지 못한 부분을 "한계 메모"에 적었는가
- [ ] 원문을 길게 그대로 저장하지 않았는가
- [ ] 로그인이 필요한 소스를 우회하려 하지 않았는가
