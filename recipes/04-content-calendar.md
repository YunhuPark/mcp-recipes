# 레시피 04. 한 달 콘텐츠 캘린더 + 소스 제작

> **Claude + Notion + Canva (+ Google Calendar)**
> 주제 몇 줄을 넣으면 한 달치 발행 계획, 카피 초안, 이미지 시안이 Notion에 정리됩니다.

| 항목 | 내용 |
|---|---|
| 결과물 | Notion 콘텐츠 캘린더 DB(발행일, 채널, 유형, 카피 초안, Canva 링크) + Canva 시안 |
| 필요한 도구 | Claude, Notion, Canva (선택: Google Calendar) |
| 난이도 | **중** (처음엔 하로 예상했으나 검증 후 상향) |
| 사전 준비 | 도구 3개 연결과 로그인 승인 (약 3분) |
| 실제 소요 시간 | 항목 8개 계획 + 시안 3개 생성 + 수정까지 **약 3분** (대부분 Canva 생성 대기) |
| 검증 일자 | 2026-10-08, 직접 실행 |

---

## 이런 분께 맞습니다
- 소상공인, 1인 마케터처럼 "이번 달에 뭘 올리지?"가 매달 반복되는 분
- 기획, 카피, 시안 제작을 따로따로 하느라 시간이 새는 분

## 이런 분께는 안 맞습니다
- 브랜드 가이드가 엄격해서 시안을 그대로 못 쓰는 팀 (결국 전부 다시 만들게 됩니다)
- 인쇄물처럼 오타 하나가 큰 비용인 작업

---

## 시작하기 전에

1. Claude에서 **Notion, Canva** 커넥터를 연결하고 로그인 승인을 합니다. (Google Calendar는 선택)
2. 아래 정보를 미리 준비하면 결과가 훨씬 좋아집니다.
   - 브랜드명 (**정확한 표기**)
   - 업종과 주요 고객
   - 이번 달 행사, 신메뉴, 프로모션
   - 쓰는 채널 (인스타그램, 스레드, 블로그 등)

---

## 진행 순서

1. **계획**: 이번 달 주제 8개와 발행일, 채널, 유형을 Claude가 제안합니다.
2. **Notion DB 생성**: 주제, 발행일, 채널, 유형, 카피 초안, Canva 링크 칸이 있는 표를 만듭니다.
3. **카피 초안 입력**: 항목마다 채널에 맞는 짧은 카피를 채웁니다.
4. **Canva 시안 생성**: 중요한 항목부터 시안을 만들고 링크를 Notion에 연결합니다.
5. **검수와 수정**: 시안의 텍스트를 읽어서 카피와 대조하고, 틀린 곳을 고칩니다. **(생략 금지)**
6. **(선택) 캘린더 등록**: 발행일을 Google Calendar에 넣습니다. 시간대는 `Asia/Seoul`을 명시하고, 알림 메일이 나가지 않도록 알림 수준을 끄세요. **등록 후 날짜가 의도한 날인지 한 번 더 조회해서 확인하세요.**

## 시작 프롬프트 (그대로 복사해서 쓰세요)

```
너는 [업종] 브랜드 '[브랜드명]'의 콘텐츠 매니저야.
[N월] 한 달 콘텐츠 캘린더를 만들어줘.

- 주요 고객: [예: 20~30대 직장인]
- 이번 달 일정: [예: 신메뉴 출시, 11/11 이벤트, 블랙프라이데이]
- 채널: 인스타그램, 스레드, 블로그
- 주 2회 발행, 총 8개

순서:
1. 주제 8개와 발행일, 채널, 유형을 먼저 표로 보여줘. 내가 확인하면 진행해.
2. 확인 후 Notion에 '[N월] 콘텐츠 캘린더' DB를 새로 만들고 항목을 넣어줘.
   (칸: 주제, 발행일, 채널, 유형, 카피 초안, Canva 링크)
3. 카피 초안을 채널 톤에 맞게 써줘. 가격, 할인율, 날짜는 내가 준 것만 쓰고
   모르는 건 '확인 필요'라고 적어줘.
4. 인스타그램 중요 항목 3개의 Canva 시안을 만들고 링크를 Notion에 넣어줘.
5. 시안의 텍스트를 읽어서 브랜드명, 가격, 날짜가 카피와 정확히 일치하는지 검사하고
   틀린 곳이 있으면 알려줘. 수정은 내 승인 후에 저장해.
```

## 실제로 돌려보고 알게 된 것

### 잘 된 것
- Notion DB 생성, 8개 항목 입력, 링크 연결이 한 번에 처리됩니다.
- Canva 시안의 분위기와 완성도가 기대보다 좋았습니다. (카페 사진 스타일 배경, 톤 반영)
- 생성된 시안의 텍스트를 읽어서 카피와 대조하는 검수를 자동화할 수 있습니다.
- 수정 시 미리보기로 변경 범위를 확인하고, 승인 후에만 저장할 수 있습니다.

### 막힌 것, 주의할 것

| 문제 | 실제로 일어난 일 | 대처 |
|---|---|---|
| **브랜드명 오타** | 시안 3개 중 2개에서 "모닝블**룸**"이 "모닝블**름**"으로 생성됨 | 5단계 검수를 반드시 하세요. 글자는 이미지가 아니라 **편집 가능한 텍스트 요소**이고, 생성 단계에서 틀리게 써넣은 것입니다. 아래 "오타를 줄이는 방법"을 참고하세요. |
| **브랜드 키트와 템플릿 없음** | 이 계정에는 브랜드 키트와 브랜드 템플릿이 모두 비어 있었고, 템플릿 검색은 현재 프레젠테이션만 지원한다고 표시됨. 템플릿에 값을 채우는 `autofill` 도구도 이 연결에는 없었음 | 브랜드 키트는 Canva에서 먼저 만들어 두세요. **템플릿 자동 채우기 경로는 이 연결에서 끝까지 갈 수 없었습니다.** |
| **연결 마찰** | 도구마다 연결과 승인이 따로 필요 | 처음 한 번만 하면 됩니다. 약 3분 예상하세요. |
| **날짜 추정** | 수능일, 블랙프라이데이 같은 기념일은 AI가 추정한 날짜였음 | 발행 전 직접 확인하세요. |
| **시안 생성 대기** | 3개를 동시에 요청해 완료까지 약 1분 걸렸고, 요청 직후엔 결과가 없어 상태를 다시 확인해야 함 | 시안은 여러 개를 한 번에 요청하세요. |
| **종일 일정 날짜 밀림** | 종일 일정을 `+09:00` 오프셋을 붙여 요청했더니 11/11이 **11/10으로 하루 앞당겨져** 저장됨 | 종일 일정은 `Asia/Seoul`을 지정한 채 **`+09:00` 오프셋을 뺀 시각**(예: `2026-11-11T00:00:00`)으로 보내세요. 이렇게 수정한 뒤 11/11로 정상 확인. (시간 지정 일정 2개는 `+09:00`이 있어도 정상이었음) |
| **캘린더 기본 시간대 UTC** | 이 계정의 캘린더 기본 시간대가 UTC | 일정을 만들 때마다 `Asia/Seoul`을 명시하세요. |

### 오타를 줄이는 방법: 시안을 복사하고 글자를 정확한 문구로 교체 (검증함)

생성 단계에서 글자를 AI가 쓰게 두면 틀릴 수 있어서, **잘 만든 시안을 복사한 뒤 텍스트 요소를 Notion의 정확한 문구로 직접 교체**하는 방식을 시험했습니다. (브랜드 템플릿 대신 쓰는 대안입니다.)

| 확인한 것 | 결과 |
|---|---|
| 복사본의 텍스트 6개를 새 문구로 교체 | 문서 데이터에서 **입력한 문자열과 정확히 일치**함. 브랜드명 요소는 건드리지 않아 "모닝블룸"이 그대로 유지됨 |
| 새 문구가 원래보다 길 때 | **상자 폭이 고정이라 줄이 바뀌며 글자가 겹치거나 잘림.** "블랙프라이데이", "20% OFF", 날짜 문구 3곳에서 발생 |
| 해당 상자의 폭을 넓히고 위치를 맞춤 | 겹침 없이 정상 표시됨 |

- **주의: 원본 시안은 그대로 두고 복사본에서만 작업하세요.**
- **주의: 교체 후 반드시 미리보기로 겹침과 잘림을 확인하세요.** 글자 수가 늘면 레이아웃이 자동으로 따라오지 않습니다.
- **한계:** 글자만 바꾸면 사진이 문구와 안 맞을 수 있습니다(예: 쿠키 사진에 블랙프라이데이 문구). 사진 교체는 아래에서 시험했습니다.

### 사진 교체 (검증함, 1건)

Canva로 새 이미지(원두 선물 포장과 머그컵)를 생성해 같은 실험 복사본에 적용했습니다.

| 확인한 것 | 결과 |
|---|---|
| **배경 사진 교체** | 성공. 배경 이미지 ID와 대체 텍스트가 새 값으로 바뀜 |
| 배경만 바꾼 직후 | **새 배경 위에 예전 컵과 쿠키 접시가 겹쳐 컵이 두 개로 보임.** 이 사진 일부는 배경이 아니라 따로 얹힌 이미지 요소였음 |
| 같은 시점의 글자 | 갈색 글자가 어두운 새 배경에서 **읽기 어려움** |
| 얹힌 이미지 요소 4개 삭제 + 글자색을 밝게 변경 | 새 배경과 정확한 문구가 맞는 하나의 시안으로 정리됨 (미리보기로 확인) |

- **주의:** 시안의 사진이 "배경 하나"가 아닐 수 있습니다. 교체 전에 읽어 둔 요소 목록에서 **큰 이미지 요소(사진 조각)와 장식 요소(테두리, 라벨, 아이콘)를 구분**해서 지우세요. 장식은 남겨야 합니다.
- **주의:** 배경이 어두워지면 글자색 대비를 확인하세요.
- **한계:** 이 시안 1건에서만 확인했습니다. 이미지 생성 자체가 계정의 생성 한도를 쓰는지는 확인하지 못했습니다. 생성된 이미지는 시안에 맞게 적용된 결과를 눈으로 보고 판단한 것이라, 이미지 품질의 일관성은 보장하지 않습니다.
- 편집은 저장하지 않고 취소했습니다. 생성된 이미지는 Canva 계정에 남아 있습니다.
- 실험에 쓴 복사본은 편집 내용을 **저장하지 않고 취소**했습니다.

### 8개 전체 시안 (검증함: 6개 성공, 2개 한도 초과로 실패)

Notion 캘린더의 8개 항목 중 앞서 만든 3개를 뺀 5개를, **문구를 DB에서 읽어** "한 글자도 바꾸지 말고 그대로 쓰라"고 지시해 만들었습니다. (2026-10-13)

| 항목 | 결과 |
|---|---|
| 11/3 인스타그램 | 성공. 문구 3개 모두 DB와 **정확히 일치**, 브랜드명도 맞음 |
| 11/17 스레드 (정사각형) | 성공. 본문 문구는 일치, **브랜드명이 "모닝블름"으로 틀림** |
| 11/12 블로그 | 성공(약 3분 20초). **브랜드명 "모닝블름"으로 틀림**, "단골 손님 후기"가 "단골 손님후기"로 **띄어쓰기가 바뀜**, 인용문에 따옴표가 **추가됨**. 디자인 크기가 11520×9216으로 나와 일반적인 블로그 이미지 크기가 아님 |
| 11/19 인스타그램 | **실패: `quota_exceeded`** ("User has exceeded their credit quota") |
| 11/24 블로그 | **실패: `quota_exceeded`** |

- **누적하면 지금까지 만든 시안 6개 중 브랜드명 오타가 4개**입니다(처음 3개 중 2개, 이번 3개 중 2개). "한 글자도 바꾸지 말고 그대로"라고 지시했는데도 새 3개 중 2개에서 틀렸습니다. **지시만으로는 오타를 막지 못합니다.** 위 "오타를 줄이는 방법"(복사 후 텍스트 교체)과 검수가 필수입니다.
- **생성 한도가 있습니다.** 이 계정에서는 한 번에 5개를 요청했을 때 4번째 요청부터 한도 초과로 실패했습니다. 남은 한도를 미리 볼 방법은 확인하지 못했습니다. **8개를 한꺼번에 만든다고 계획하면 안 됩니다.** 한도가 풀린 뒤에 다시 시도하거나, 시안 1개를 만들어 복사한 뒤 문구만 교체하는 방식(한도를 덜 쓰는 것으로 보이지만 미확인)을 쓰세요.
- 검수를 통과한 시안(11/3)만 Notion에 링크하고, 오류가 있는 시안은 수정 전이라 링크하지 않았습니다. **검수 전에는 링크하지 않는 것이 안전합니다.**
- 요구 문구 9개 중 **6개 정확히 일치**, 1개 띄어쓰기만 다름, 2개(브랜드명) 글자가 틀림. 시안 3개의 결과이므로 일반화하지 마세요.
- 소요 시간: 요청 5개를 보내고 읽기와 대조, Notion 링크까지 **약 4분 20초**(대부분 시안 생성 대기, 블로그 시안이 가장 오래 걸림).

### 아직 검증하지 못한 것 (솔직하게 밝힙니다)
- **Google Calendar 등록은 3개만 검증했습니다.** 종일 일정 1개, 시간 지정 일정 1개(11/5 10:00 KST), 날짜 경계 일정 1개(11/3 00:30 KST)를 등록했고, 시간 지정 2개는 한국 시각 그대로 정상이었습니다. 종일 일정은 위 표의 날짜 밀림 문제가 있었고 수정으로 해결했습니다. 8개 전체 등록, 반복 일정, 참석자 초대는 검증하지 않았습니다.
- **브랜드 키트 반영 결과**: 이 계정에는 키트가 없어서 확인하지 못했습니다.
- **브랜드 템플릿 자동 채우기**: 템플릿이 없고 `autofill` 도구도 없어서 끝까지 해보지 못했습니다. 다른 플랜이나 연결에서는 다를 수 있습니다.
- **이미지 교체는 시안 1건만 시험했습니다.** 여러 시안과 다른 이미지 스타일에서의 안정성은 확인하지 못했습니다.
- **8개 전부의 시안 생성**: 6개만 만들었습니다. 나머지 2개(11/19, 11/24)는 생성 한도 초과로 실패했고, 한도가 풀린 뒤에 만들 수 있는지는 확인하지 못했습니다.
- **블로그 시안의 크기**: 11520×9216으로 나왔는데 실제 블로그에서 쓸 수 있는지는 확인하지 못했습니다.
- **다른 업종**: 카페(가상 브랜드) 1건만 테스트했습니다.

## 확장편: Threads 자동 발행 — 개발자용 고급편 (알고 파이프라인 기준)

> ⚠️ **코드를 쓸 수 있는 분을 위한 고급편**입니다. 위의 1~6단계(Claude + Notion + Canva)는 코드 없이 따라 할 수 있지만, Threads 발행은 API 호출 코드가 필요합니다.
>
> 이 섹션은 공개 저장소 [알고(algo-pipeline)](https://github.com/YunhuPark/algo-pipeline)의 README와 코드를 읽고 작성했습니다. **Threads에 실제로 게시해 본 적은 없습니다.** 계정과 토큰으로 실행한 검증이 없다는 뜻이고, 아래 "확인한 것"은 코드를 읽어서 알게 된 내용입니다.

### 알고는 어떤 프로젝트인가

AI/테크 뉴스를 수집하고, 출처 근거를 검증한 뒤, 카드뉴스 이미지를 만들어 Instagram에 게시하는 로컬 자동화 시스템입니다(Python, SQLite, MIT 라이선스). 이 레시피와 관련해서 중요한 점은 기능이 아니라 **자동 게시를 얼마나 보수적으로 설계했는가**입니다.

### 알고가 자동 게시를 다루는 방식

README와 코드에서 확인한 내용입니다.

| 원칙 | 알고의 구현 | 이 레시피에 주는 교훈 |
|---|---|---|
| **기본은 차단** | `AUTO_UPLOAD=false`, `DRY_RUN=true`가 기본값이고, `ALGO_ENV=production`을 포함한 세 값이 모두 맞을 때만 실제 게시 | 드라이런을 기본으로 두고, 켜는 건 사람이 명시적으로 |
| **호출 전에 기록** | publisher를 호출하기 *전에* 게시 시도를 DB에 기록(durable attempt) | 상태를 "발행 후"가 아니라 **"발행 전"** 에 기록 |
| **불확실하면 재시도 금지** | 빈 원격 ID, 저장 실패, 오래된 시도는 자동 reset·retry 하지 않음 | 올라갔는지 모르는 상태에서 다시 올리면 중복 게시 |
| **우회 경로 차단** | 직접 주제 게시, 저장된 폴더 업로드, 대시보드 직접 게시를 막아 둠 | 발행 경로는 **하나만** 둡니다 |
| **근거 검증** | 근거와 연결된 claim만 렌더링과 게시 단계로 전달 | 가격, 날짜, 브랜드명을 발행 직전에 다시 대조 |

### Threads 발행의 현재 상태 (알고 기준)

- `src/agents/threads_publisher.py`에 Threads **캐러셀(이미지 여러 장) 게시**가 구현되어 있습니다. 이미지 컨테이너 생성 → 캐러셀 컨테이너 생성 → 처리 상태 대기 → 게시 순서입니다.
- 토큰은 `THREADS_ACCESS_TOKEN`, 계정은 `THREADS_USER_ID`를 쓰고, **없으면 Instagram 값으로 대체**합니다. 설정을 잘못하면 의도하지 않은 계정에 올라갈 수 있어서, 고급 사용자는 이 대체 동작을 끄는 게 안전합니다.
- 이미지는 **공개 URL**이 필요합니다(ngrok 터널 또는 `IG_IMAGE_BASE_URL`). Canva 시안을 쓸 때도 공개 URL을 어떻게 만들지는 별도로 정해야 합니다.
- **Queue V2의 안전한 게시 경로(시도 기록, 승인)에는 연결되어 있지 않습니다.** 실제로 `main.py "주제" --threads`가 승인 없이 Threads 게시 코드까지 이어지는 경로여서, 2026-10-09에 [PR #12](https://github.com/YunhuPark/algo-pipeline/pull/12)로 `--threads`를 모든 모드에서 차단했습니다.

이 마지막 항목이 핵심 교훈입니다. **"게시 코드가 있다"와 "안전하게 자동 발행된다"는 다릅니다.** 게시 호출을 붙이는 것보다 상태 기록, 승인, 재시도 금지를 먼저 설계해야 합니다.

### 설계: 알고의 방식을 Notion 레시피에 적용하기

**Notion DB 칸**

| 칸 | 값 |
|---|---|
| 상태 | 초안 / 검수완료 / **발행승인** / **발행중** / 발행됨 / **불확실(수동 확인)** / 실패 |
| 발행 URL | URL |
| 발행 시각 | 날짜 |

**발행 순서**

1. **대상 선택**: 채널이 "스레드"이고 상태가 "발행승인"인 항목만. 사람이 상태를 바꾸는 것이 유일한 발행 트리거입니다.
2. **사전 검사**: 500자 이내인지, 브랜드명, 가격, 날짜가 Notion 원본과 일치하는지. 하나라도 어긋나면 중단합니다.
3. **미리보기 (기본값)**: 올릴 내용만 출력하고 게시하지 않습니다. 사람이 "발행해"라고 해야 다음으로 넘어갑니다.
4. **API 호출 전에 상태를 "발행중"으로 기록**합니다. 알고의 durable attempt와 같은 역할입니다.
5. 컨테이너를 만들고 발행합니다.
6. 응답에 게시 ID가 있고 Notion 기록도 성공하면 "발행됨"과 발행 URL을 기록합니다.
7. 응답이 비어 있거나, 기록이 실패했거나, 중간에 끊기면 **"불확실"** 로 둡니다. **자동 재시도는 하지 않고**, 사람이 Threads에서 실제로 올라갔는지 확인한 뒤 상태를 정합니다.

4번과 7번이 이 설계의 핵심입니다. 상태를 발행 *후*에만 기록하면, 도중에 실패했을 때 올라갔는지 알 수 없고 다시 시도하면 같은 글이 두 번 올라갑니다.

### 사전 준비 (웹 검색 기준, 직접 확인하지 않음)

- Meta 개발자 계정과 앱이 필요합니다.
- 권한은 `threads_basic`(필수), `threads_content_publish`(게시), `threads_manage_replies`(답글)입니다.
- 앱 심사를 받기 전에는 **본인 계정과 앱 테스터 계정에만** 게시할 수 있습니다. 내 계정 하나에 올리는 용도라면 이 범위로 충분합니다.
- 액세스 토큰은 만료되므로 갱신 관리가 필요합니다. 정확한 유효기간과 절차는 [공식 문서](https://developers.facebook.com/docs/threads/overview)를 확인하세요.
- 한도는 게시 24시간당 250개, 답글 1,000개입니다.
- 알고 저장소의 `docs/runbooks/instagram-auth-setup.md`는 같은 Meta 플랫폼의 인증 절차를 다루지만, **저는 읽어보지 않았고** Instagram용이라 Threads에 그대로 적용되는지는 모릅니다. 참고만 하세요.

### 발행 방식 비교

| 방식 | 장점 | 단점 |
|---|---|---|
| **API 직접 호출** (알고 방식) | 상태 기록과 재시도 정책을 직접 통제 | 코드와 토큰 관리 필요 |
| Zapier / n8n | 코드 없이 구성 가능 | Threads 지원 범위, 요금, **상태 기록을 세밀하게 통제하기 어려움**은 확인 필요 |
| MCP 서버 | 대화로 제어 가능 | 공식 Threads 발행 MCP는 **확인하지 못함** |

### 시작 프롬프트 (Claude Code로 구현할 때)

```
알고(algo-pipeline)의 src/agents/threads_publisher.py를 참고해서,
Notion '[N월] 콘텐츠 캘린더' DB의 Threads 항목을 발행하는 스크립트를 만들어줘.

요구사항:
- 대상은 채널='스레드'이고 상태='발행승인'인 항목만.
- 기본은 드라이런(미리보기만). --publish 옵션이 있을 때만 실제 게시.
- 발행 직전에 500자, 브랜드명, 가격, 날짜를 Notion 원본과 대조하고 어긋나면 중단.
- API 호출 전에 상태를 '발행중'으로 기록하고,
  성공하면 '발행됨'과 URL, 응답이 비었거나 기록이 실패하면 '불확실'로 둬.
- '불확실'과 '실패'는 자동 재시도하지 마.
- 토큰은 환경변수에서만 읽고, Instagram 토큰으로 대체하지 마.
- 실제 게시 테스트는 하지 말고, API 호출은 모킹한 테스트만 작성해줘.
```

### 이 확장편에서 아직 모르는 것

- `threads_publisher.py`를 실제 계정과 토큰으로 실행하면 어떻게 동작하는지
- Threads를 알고의 Queue V2 시도 기록에 연결했을 때의 동작
- Canva 시안을 Threads가 가져갈 수 있는 공개 URL로 제공하는 방법
- Meta 앱 설정과 토큰 발급에 실제로 걸리는 시간, 토큰 유효기간과 갱신 방법의 최신 절차
- 예약 발행 지원 여부, Zapier와 n8n의 Threads 지원 범위
- 자동 게시 계정이 받을 수 있는 불이익(스팸 분류 등)
