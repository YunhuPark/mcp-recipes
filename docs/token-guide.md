# Threads 토큰 발급 가이드 (본인 계정에 글을 올리는 용도)

> **이 순서는 공식 문서(2026-10-20 확인)를 근거로 정리한 것이고, 실제로 따라 해 본 것은 아닙니다.** 대시보드의 화면 이름과 위치는 달라질 수 있습니다. 막히면 화면에 보이는 문구(값은 가리고)를 기준으로 판단하세요.
> 앱 시크릿, 토큰, 승인 코드는 채팅, 스크린샷, 저장소 어디에도 붙여넣지 마세요.

걸리는 시간은 처음이면 20~30분 안팎입니다. 필요한 것은 **본인 Threads 계정**과 **Meta(Facebook) 로그인**입니다.

## 1. 앱 만들기

1. <https://developers.facebook.com> 에 본인 계정으로 로그인합니다. 개발자 등록 화면이 나오면 안내에 따라 진행합니다.
2. **내 앱 > 앱 만들기**를 누릅니다.
3. 사용 사례에서 **"Threads API 액세스"(Access the Threads API)** 를 고릅니다. 앱 이름은 아무거나 괜찮습니다. 비즈니스 포트폴리오 연결 등 선택 항목은 건너뛸 수 있으면 건너뜁니다.
4. 앱이 만들어지면 **Meta 앱 ID와 Threads 앱 ID가 따로 생깁니다.** 이후에는 **Threads 앱 ID와 Threads 앱 시크릿**만 씁니다.

## 2. 사용 사례 설정

1. 왼쪽 메뉴 **사용 사례(Use cases)** 에서 Threads 사용 사례를 열고(맞춤 설정) 권한을 추가합니다.
   - `threads_basic` (필수, 기본 포함)
   - `threads_content_publish` (글 올리기)
   - `threads_manage_insights` (조회 수 읽기, `scripts/insights.py`용)
   - `threads_read_replies` (댓글 읽기. 요청 댓글을 세는 데 쓰며 읽기만 한다)

   **나머지 권한은 추가하지 않는다 (최소 권한 원칙).** 토큰이 새면 그 권한만큼의 일을 남이 할 수 있다.
   `threads_delete`(글 삭제), `threads_manage_replies`(내 이름으로 답글 쓰기와 숨기기), `threads_share_to_instagram`(인스타그램에 대신 올리기)는 지금 필요가 없고 위험만 늘린다.
   `threads_keyword_search`, `threads_profile_discovery`, `threads_location_tagging`, `threads_manage_mentions`도 쓰지 않는다.
   나중에 필요하면 대시보드에서 언제든 추가할 수 있지만, **권한은 토큰을 받을 때 정해지므로** 추가한 뒤에는 `get_token.py`를 다시 실행해 토큰을 새로 받아야 한다(`--scopes`로 권한 목록을 바꿀 수 있음).
   `get_token.py`의 기본 권한은 위 4개이고, **대시보드에 추가한 권한과 같아야 한다.** 대시보드에 없는 권한을 요청하면 승인 단계에서 오류가 난다.
2. 같은 사용 사례의 **설정(Settings)** 에서 **Threads 앱 ID**와 **Threads 앱 시크릿**을 확인합니다. 시크릿은 눈에 띄지 않게 보관하세요.
3. **Client OAuth Settings(유효한 OAuth 리디렉션 URI)** 에 주소 하나를 등록합니다.
   - 승인이 끝나면 브라우저가 이 주소로 이동하고, **주소창에 `code=...`가 붙습니다.** 그 페이지가 열리지 않아도 됩니다. 주소만 보면 됩니다.
   - 추천: `https://localhost/`. 문서에는 localhost나 HTTPS 여부가 명시되어 있지 않아서, 저장이 거절되면 본인이 가진 아무 `https://` 주소로 바꿉니다.
   - **나중에 입력할 값과 한 글자도 다르면 안 됩니다.** 대시보드가 끝에 `/`를 붙이는 경우가 있으니 저장 뒤 목록에 표시된 값을 그대로 씁니다.
4. **Deauthorize callback URL**, **Data Deletion Requests URL** 칸은 문서상 앱을 게시할 때의 요건입니다. 본인 계정에만 쓰는 개발 모드에서는 비워 둘 수 있으면 비워 두고, 필수라고 막으면 임시로 위와 같은 `https://` 주소를 넣습니다. (확인하지 못한 부분)
5. **저장(Save)** 을 누릅니다.

## 3. 본인을 테스터로 등록

1. 설정 화면의 **"Add or Remove Threads Test Users"** 를 눌러 **앱 역할 > 역할**로 이동합니다.
2. **사람 추가(Add People)** 에서 **Threads 테스터(Threads Tester)** 를 고르고 본인 Threads 사용자 이름을 입력합니다.
3. **Threads 앱 또는 웹에서 초대를 수락**합니다: 계정 설정 > **웹사이트 권한(Website permissions)** 에서 초대를 수락합니다. 이걸 빼먹으면 승인 단계에서 오류가 납니다.

앱을 **게시(Publish)** 할 필요는 없습니다. 문서에서 앱 심사와 게시는 역할이 없는 다른 사용자가 쓸 때의 이야기이고, 본인은 역할(테스터)이 있기 때문입니다.

## 4. 토큰 받기

방법이 둘입니다. **A가 더 쉽고, 리디렉션 URI가 필요 없습니다.**

### 방법 A (권장): 대시보드의 "사용자 토큰 생성기"

(2026-10-20 실제 대시보드 화면에서 확인한 기능입니다.) **이용 사례 > Threads API > 설정** 화면 아래쪽에 **"사용자 토큰 생성기"** 가 있고, "이 앱의 Threads 테스터용 장기 액세스 토큰을 생성합니다"라고 적혀 있습니다. 먼저 3번(테스터 등록과 수락)이 끝나 있어야 합니다.

1. 사용자 토큰 생성기에서 본인 계정을 고르고 **토큰을 생성**합니다. 권한 승인 창이 뜨면 본인 계정으로 승인합니다.
2. 나온 토큰을 **복사**합니다 (채팅에 붙여넣지 마세요).
3. 본인 터미널에서 실행합니다.

   ```bash
   python scripts/get_token.py --from-token
   ```
4. 토큰을 붙여 넣으면(화면에 보이지 않습니다) **읽기 전용 호출 하나로 토큰이 유효한지 확인**하고, `y`를 입력하면 환경 변수 3개를 저장합니다. 발급 시각을 알 수 없어 만료일은 "오늘부터 60일"로 추정합니다. 대시보드에 표시된 만료일이 다르면 `THREADS_TOKEN_EXPIRES`를 직접 고치세요.

### 방법 B: 승인 코드로 받기 (도우미 스크립트)

리디렉션 URI 등록이 필요합니다. 2026-10-20에 `https://localhost/`를 등록하려 하니 "Redirect URIs: OAuth 리디렉션 URI를 지정해주세요"라며 저장이 거절되는 것을 확인했습니다(localhost는 받지 않는 것으로 보임). 이 방법을 쓰려면 `localhost`가 아닌 `https://` 주소(예: `https://example.com/`)를 **세 칸(리디렉션, 제거, 삭제 콜백) 모두**에 넣고 저장하세요. 승인 뒤 그 페이지가 열려도 주소창의 `code=...`만 있으면 됩니다.

**본인 터미널에서** 실행합니다 (Claude는 비밀값을 보지 않기 위해 이 스크립트를 실행하지 않습니다).

```bash
python scripts/get_token.py
```

화면이 시키는 대로 합니다.

1. **Threads 앱 ID**를 입력합니다 (눈에 보이는 입력).
2. 등록한 **리디렉션 URI**를 입력합니다.
3. 출력된 **주소를 브라우저에서 열어** 본인 Threads 계정으로 승인합니다.
4. 승인 뒤 이동한 페이지의 **주소창 전체를 복사**해서 붙여 넣습니다 (화면에 보이지 않습니다). 끝에 붙는 `#_`는 자동으로 처리합니다.
5. **Threads 앱 시크릿**을 붙여 넣습니다 (화면에 보이지 않습니다).
6. 성공하면 사용자 ID와 **만료 예정일(60일 뒤)** 이 나옵니다. 값 자체(토큰, 시크릿, 코드)는 **출력하지 않습니다.**
7. `y`를 입력하면 이 PC의 **사용자 환경 변수** 3개(`THREADS_ACCESS_TOKEN`, `THREADS_USER_ID`, `THREADS_TOKEN_EXPIRES`)에 저장합니다. 그 외를 입력하면 저장하지 않고 토큰을 버립니다. `THREADS_LIVE`는 일부러 저장하지 않습니다.

승인 코드는 **1시간 안에, 한 번만** 쓸 수 있습니다. 실패하면 3번부터 다시 하세요.
직접 환경 변수를 넣고 싶으면 `python scripts/get_token.py --show-token`으로 값을 화면에 보여 달라고 할 수 있습니다(저장은 하지 않음. 화면 기록에 남으니 주의).

## 5. 확인

**새 터미널을 열고**(환경 변수가 반영되도록) 실행합니다.

```bash
python scripts/post.py --check-token
```

- 성공: "토큰이 유효하고 THREADS_USER_ID 와 같은 계정입니다"가 나옵니다. 이 호출은 읽기 전용이고 아무것도 게시하지 않습니다.
- 실패: 나온 오류 문장을 알려 주세요 (값은 이미 가려져 있습니다). 코드는 문서에 나온 `graph.threads.com`을 쓰는데, 오류가 도메인 때문이면 고치겠습니다.

## 막히기 쉬운 곳

| 증상 | 가능한 원인 |
|---|---|
| 리디렉션 URI 오류 | 대시보드에 등록한 값과 한 글자라도 다름 (끝의 `/` 포함) |
| 권한(scope) 오류 | 사용 사례에서 해당 권한을 추가하지 않음 |
| 승인 단계에서 오류 | 테스터 초대를 수락하지 않음 |
| 코드 교환 실패 | 코드를 이미 썼거나 1시간이 지남, 또는 앱 시크릿이 Meta 앱 쪽 것임 (Threads 앱 시크릿이어야 함) |
| `--check-token`이 다른 계정이라고 함 | `THREADS_USER_ID`가 승인한 계정과 다름 |

## 관리

- 장기 토큰은 **60일** 뒤 만료됩니다. 발급 24시간 뒤부터 만료 전까지 갱신할 수 있고(`GET /refresh_access_token`), 갱신하면 `THREADS_TOKEN_EXPIRES`도 고칩니다. 갱신 도우미는 아직 없습니다. `post.py --status`가 만료 14일 전부터 경고합니다.
- **비밀값이 노출됐다면** 대시보드에서 앱 시크릿을 재설정하고, 토큰은 Threads 설정의 웹사이트 권한에서 앱 권한을 삭제한 뒤 다시 발급하세요.
- 환경 변수는 새로 연 터미널에만 반영됩니다. 이미 열려 있던 터미널에서는 보이지 않을 수 있습니다.
