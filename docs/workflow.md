# 운영 방법: 글 만들고 올리기 (Claude 없이 할 수 있는 부분)

Claude(AI)의 사용량이 드는 일은 **새 시험을 돌려 글감을 만드는 일**과 **글이 근거와 맞는지 판단하는 일**입니다. 나머지는 스크립트로 처리합니다.

## 글 하나의 흐름

| 단계 | 명령 | 누가 |
|---|---|---|
| 1. 뼈대 만들기 | `python scripts/new_post.py D10 --slug my-post --title "제목"` | 스크립트 |
| 2. 본문과 근거표 쓰기 | 파일의 코드 블록(본문)과 `## 근거표`를 채운다. 사실 주장마다 한 행(근거 파일, **그 파일에 그대로 있는 문구**, 결과) | 사람 또는 Claude |
| 3. 대조 기록 | `python scripts/check.py --stamp D10` (대조를 끝낸 뒤에만. 이후 본문을 고치면 점검이 실패한다) | 사람 |
| 4. 확정 | `python scripts/approve.py D10` (점검을 통과해야 하고, 마지막에 **사람이 `yes`** 를 입력) | 사람 |
| 4'. 한 주치를 한 번에 확정 | `python scripts/approve.py --batch` (초안 전부를 한 번에 보여 주고 `yes` 한 번으로 확정. 하나라도 점검에 실패하면 전체 중단. 먼저 `--batch --dry-run` 으로 점검만 해 볼 수 있음) | 사람 |
| 5. 올리기 | `python scripts/post.py D10 --topic "AI Threads"` 로 미리보기, `$env:THREADS_LIVE="yes"; python scripts/post.py D10 --publish --topic "AI Threads"` | 사람 (스케줄러가 열리면 자동) |
| 6. 숫자 기록 | `python scripts/insights.py --write` ("게시 후 기록"에 조회와 API 값을 적음) | 스크립트 |
| 7. 요청 댓글 | 댓글을 읽고 직무나 도구를 구체적으로 적은 것만 "요청한 사람" 칸에 직접 적는다 | 사람 |

각 단계에서 **커밋은 하지 않습니다.** 마지막에 `python scripts/check.py` 를 돌리고 직접 커밋하세요.

## 토큰(사용량)을 아끼는 운영

1. **일주일치를 한 번에.** 월요일에 그 주 글을 한 세션에서 만들고(근거표 포함), 사람이 한 번에 읽고 `approve.py --batch` 로 확정합니다. 확정한 글은 스케줄러가 매일 하나씩 올리고, 올리는 순간에도 `check.py` 가 돌아 **그사이 근거 문서가 바뀌어 인용이 사라졌거나 본문이 바뀐 글은 자동으로 멈춥니다.** (회고, 집계 글처럼 그 주 결과에 달린 글은 미리 만들 수 없어 비워 둡니다.) 매일 오가는 것보다 대화가 훨씬 줄어듭니다.
2. 글을 직접 쓰는 경우 3번(`--stamp`)까지 끝내면 4번에서 `check.py` 가 **인용이 근거 파일에 실제로 있는지**, **대조 뒤 본문이 바뀌지 않았는지**를 자동으로 막아 줍니다.
3. 일상 작업(초안, 점검)은 가벼운 모델로, 새 시험 설계처럼 어려운 일만 큰 모델로 돌립니다.
4. 조회 수는 `insights.py --write` 로 기록합니다 (토큰 필요).

## 기계가 못 하는 것

- **근거가 주장을 정말 뒷받침하는지**는 사람이 읽고 판단해야 합니다. 지금까지 잡은 오류(과장된 표현, 근거와 다른 숫자)는 모두 이 단계에서 나왔습니다. 도구는 인용이 **있는지**만 확인합니다.
- 요청 댓글인지 아닌지의 판단.

## 상태 규칙

- `초안` 글만 `approve.py` 로 확정할 수 있고, 일정표도 `초안`이어야 합니다.
- 확정한 글의 본문을 고치면 점검이 실패하므로 `초안`으로 되돌리고 다시 대조해야 합니다.
- 도구로 올리는 글은 `검수완료`여야 하고, 하루 1개까지입니다.
